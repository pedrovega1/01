# «В монитор» — сайт с эффектом погружения в экран

Концепт по мотивам [fanalis.in](https://www.fanalis.in/): приветственное интро → кнопка →
сцена с компьютером на столе → при скролле камера «въезжает» в монитор, и внутри
экрана начинается основной контент сайта.

---

## 1. Как устроен оригинал (fanalis.in)

Это Awwwards-сайт студии Fanalis Compose. Разбор по экранам:

### Экран 1 — Интро / Hero («The Web — a remake»)
- Тёмная «комната» в перспективе (стены, плиточный пол, лёгкие частицы-пылинки).
- По центру на деревянном столе стоит **ретро-компьютер с лампой** (CRT-монитор + клавиатура).
- Текст сверху вниз:
  - `FANALIS COMPOSE PRESENTS`
  - крупный заголовок **`The Web`** (засечный шрифт, типа Playfair / Canela)
  - подзаголовок курсивом `a remake`
  - кнопка **`▶ WATCH NOW`** (поверх монитора)
  - ссылка `WATCH LATER, SKIP TO THE SITE` (пропустить интро)
  - внизу: `A SHORT FILM ABOUT THE WEB` / `WRITTEN & DIRECTED BY THE FANALIS TEAM`
- Сбоку плашка-бейдж `Nominee` (Awwwards).

### Дальше (при взаимодействии / скролле)
- Нажатие на `WATCH NOW` запускает видео-интро; `SKIP` ведёт сразу на основной сайт.
- При скролле **камера приближается к монитору** — стол и комната уходят за края,
  кадр заполняется экраном, и контент «переезжает внутрь» монитора.
- Дальше идёт обычный контент студии: работы/кейсы, услуги, о команде, контакты.

### Технологии (типовой стек таких сайтов)
- **Lenis** — инерционный «умный» скролл (smooth scroll).
- **GSAP + ScrollTrigger** — привязка анимаций к прогрессу скролла (scrub).
- **Three.js / WebGL** или **видео-секвенция кадров** — для 3D-сцены и зума в монитор.
- Засечная типографика (display-serif) + моноширинный/трекинговый caps для подписей.
- Палитра: почти чёрный фон `#0a0a09`, тёплый бежевый свет от лампы, белый текст.

## 2. Что хотим сделать (наша версия)

Три фазы по таймлайну скролла:

```
[ФАЗА 0]  Приветственное окно (модалка)
            └─ кнопка "Войти" → окно исчезает
                  │
[ФАЗА 1]  Сцена: компьютер на столе стоит (статично, hero)
            └─ подсказка "скролльте вниз ↓"
                  │  (пользователь скроллит)
[ФАЗА 2]  Зум в монитор: камера/scale приближается к экрану,
          окружение уходит за края → экран на весь viewport
                  │
[ФАЗА 3]  Контент "внутри монитора" — основной сайт
```

### Поведение по шагам
1. **Загрузка** → поверх всего модальное приветственное окно (затемнённый фон).
2. **Клик по кнопке** → модалка плавно исчезает (fade/scale out), скролл разблокируется.
3. **Hero** → видно компьютер на столе по центру; страница «держится» (pin), пока идёт зум.
4. **Скролл** → прогресс анимации (scrub): монитор масштабируется к центру экрана,
   стол/комната разъезжаются и затемняются, рамка экрана растёт до краёв viewport.
5. **Завершение зума** → экран монитора = весь экран, внутри проявляется контент сайта.

## 3. Что уже собрано (Three.js-прототип)

Реализован рабочий прототип на Three.js (выбран подход «как оригинал»).
Сцена комнаты собрана из примитивов — внешние .glb-модели не нужны, запускается сразу.

```
01/
├─ index.html              # модалка + canvas сцены + секции контента
├─ README.md               # этот файл
├─ src/
│  └─ main.js              # Three.js сцена, dolly-in по скроллу, логика фаз
├─ styles/
│  └─ main.css             # стили модалки, hero, контента, палитра
└─ .claude/launch.json     # конфиг локального сервера для preview
```

Зависимости подключены через **importmap + CDN** (three, gsap) — без npm/сборки.

### Как запустить
ES-модули и importmap требуют http (не `file://`). Подними любой статик-сервер:
```
python -m http.server 8124
```
и открой `http://localhost:8124/index.html`.

### Проверено end-to-end
- Фаза 0 — приветственная модалка с кнопкой «Войти» ✓
- Фаза 1 — комната + стол + CRT-монитор с зелёным терминалом и тёплым светом лампы ✓
- Фаза 2 — dolly-in: камера въезжает в экран по скроллу (`#scroll-driver`, 300vh) ✓
- Фаза 3 — на финале зума проявляется HTML-контент «внутри монитора» ✓

### HTML-каркас (логика секций)
```html
<!-- Приветственное окно -->
<div id="intro-modal">
  <h1>The Web</h1>
  <button id="enter-btn">▶ ВОЙТИ</button>
</div>

<!-- Сцена с компьютером (pinned на время зума) -->
<section id="scene">
  <div class="room"></div>
  <div class="desk"></div>
  <div class="computer">
    <div class="screen"><!-- сюда «въезжаем» --></div>
  </div>
</section>

<!-- Контент внутри монитора -->
<main id="site-content">
  <!-- работы, услуги, о нас, контакты -->
</main>
```

## 4. Технический рецепт эффекта «въезд в монитор»

Самый надёжный способ без 3D — **CSS `transform: scale()` + `transform-origin` в центр экрана монитора**, привязанный к скроллу через GSAP ScrollTrigger.

```js
// псевдокод main.js
import Lenis from 'lenis';
import gsap from 'gsap';
import { ScrollTrigger } from 'gsap/ScrollTrigger';
gsap.registerScrollTrigger?.(); // registerPlugin(ScrollTrigger)

// 1. Smooth scroll
const lenis = new Lenis();
gsap.ticker.add((t) => lenis.raf(t * 1000));
ScrollTrigger.update && lenis.on('scroll', ScrollTrigger.update);

// 2. Приветственное окно
document.querySelector('#enter-btn').addEventListener('click', () => {
  gsap.to('#intro-modal', { autoAlpha: 0, scale: 1.05, duration: 0.8,
    onComplete: () => document.body.classList.remove('locked') });
});

// 3. Зум в монитор (scrub-таймлайн, секция запинена)
const tl = gsap.timeline({
  scrollTrigger: {
    trigger: '#scene',
    start: 'top top',
    end: '+=200%',     // длина зума
    scrub: true,
    pin: true,
  }
});
tl.to('.room',     { scale: 1.4, opacity: 0 }, 0)
  .to('.desk',     { y: 400, opacity: 0 }, 0)
  .to('.computer', { scale: 8, transformOrigin: 'center 42%' }, 0) // 42% ≈ центр экрана
  .to('.screen .frame', { opacity: 0 }, 0.7)   // рамка исчезает на финале
  .fromTo('#site-content', { opacity: 0 }, { opacity: 1 }, 0.85);
```

Ключевой момент: `transform-origin` ставим точно в **центр экрана монитора**
(не в центр картинки компьютера), иначе зум уедет вбок. Значение подбирается под арт.

> Вариант «по-взрослому»: Three.js с 3D-моделью комнаты и камерой, которую двигаем
> dolly-in по треку скролла. Дороже, но даёт настоящую перспективу как в оригинале.

## 4b. PS1-стиль (реализовано)

В сцену добавлена эстетика PlayStation 1 — параметры вверху [src/main.js](src/main.js):
- `PS1_PIXEL` — рендер в низком разрешении (`renderer.setSize / PS1_PIXEL`), CSS
  `image-rendering: pixelated` растягивает обратно → крупный пиксель.
- `PS1_SNAP` — **vertex jitter**: вершины привязываются к грубой сетке в clip-space
  через `material.onBeforeCompile` (инъекция после `#include <project_vertex>`).
- `flatShading: true` на всех материалах → гранёное «вершинное» освещение.
- `NearestFilter` на текстуре экрана + `antialias: false` → без сглаживания.
- `makePS1(material)` применяется ко всем мешам через `scene.traverse`.

Подкрутка: больше `PS1_PIXEL` = крупнее пиксель; меньше `PS1_SNAP` = сильнее дрожь.

### Модели (подключены)
В `assets/` лежат три GLB, они загружаются в [src/main.js](src/main.js):
- **Table.glb** — стол (верх столешницы ≈ y=1.0), стоит в центре на полу.
- **pc.glb** — компьютер на столе. Экран — меш `mesh_id49`; поверх него кладётся
  живой `CanvasTexture` (зелёный CRT-терминал), в который и «въезжает» камера.
  Если монитор смотрит от камеры — поверни флагом `PC_ROT_Y = Math.PI`.
- **Camera.glb** — видеокамера слева-сзади как фоновый реквизit.

Позиция экрана и трек dolly считаются **динамически** из мирового bounding box
`mesh_id49` после загрузки (важно: перед расчётом — `pcObj.updateMatrixWorld(true)`).
`makePS1` применяется ко всем мешам моделей через `applyPS1Tree`.

Другие источники low-poly/PS1 моделей: [Poly Pizza](https://poly.pizza/),
[Quaternius](https://quaternius.com/), [Sketchfab ps1](https://sketchfab.com/tags/ps1),
[Meshy](https://www.meshy.ai/tags/ps1).
